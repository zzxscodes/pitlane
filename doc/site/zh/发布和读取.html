发布和读取

Desk 有十一条环：intents、reports、quotes、algos、controls、pulses、prints、queries、pack_reqs、pack_rsps 和 logs。编译期容量对齐 trade lane / package lane：kIntentCap/kReportCap/kAlgoCap 32768、kQuoteCap 8192、kControlCap 16384、kPulseCap/kPrintCap 4096、kQueryCap 1024、kPackReqCap/kLogCap 2048、kPackRspCap 16384。经 desk_apply_conf / FanRing::tune 后的软容量不超过该上限，由 capacity() 报告。资金和持仓在 cash（kCashCap 512）与 hold（kHoldCap 4096）里。

publish 接收一条消息和一个读者掩码。掩码为 0 时，第一个确认的读者取走这个槽。其他掩码列出必须确认的读者，这些读者都确认之后槽才能再次使用。读者编号从 0 到 63。会话循环是读者 7，也就是 kLoopReader。


pitlane::Intent in{};
in.tag = 1;
in.name = 1;
in.acct = 2;
in.px = 100;
in.qty = 5;
in.stamp_us = 1;
in.side = static_cast<uint8_t>(pitlane::Side::Buy);
in.act = static_cast<uint8_t>(pitlane::Act::Enter);
in.style = static_cast<uint8_t>(pitlane::Style::Day);

const uint64_t readers = 1ull << pitlane::kLoopReader;
if (!desk->intents.publish(in, readers)) {
    // 环已满，这张新单没有写入。
}

读者用 at 复制一个槽。位置是绝对序号，从 0 开始。这个读者还没有确认时，fresh 为真。ack 记下这次确认。latest 复制最新发布的一条。tail 是写入者下一次要使用的位置。


pitlane::Intent got{};
bool fresh = false;
if (desk->intents.at(0, pitlane::kLoopReader, got, &fresh) && fresh) {
    desk->intents.ack(0, pitlane::kLoopReader);
}

Intent、Report 和 Quote 在 desk/types.hpp。其余槽类型——AlgoJob、ControlNote、Pulse、TapePrint、QueryNote、SubNote、SigNote、MktNote、PackageNote、LogNote——在 desk/wire.hpp。比这些槽更大的数据，由调用方放在自己的环上，类型是 Parcel<Bytes>。长度大于 Bytes 时，publish_parcel 失败。热路径可用 desk_log_publish 写入 LogNote，冷侧再排空 logs 环。WireLog 对齐笔记里的异步日志：log 把一行打进一个 PackedLine（字面量用 lit，动态串拷进槽，标量 memcpy），满环丢弃该行，热路径不格式化。后台线程或调用方 flush 再把槽写成文本。日志文件放 tmpfs，热路径就不碰块设备。
